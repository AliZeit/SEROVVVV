# Цель работы:

Изучить процесс загрузки системы, научиться настраивать загрузчик GRUB2, работать с параметрами ядра и понимать их влияние на систему. Научиться самостоятельно определять особенности дистрибутива и применять корректные команды.

**Оборудование:** Виртуальная машина с Linux (Astra Linux, ROSA Linux, Fedora, Ubuntu, Debian и др.)

> **О форме отчётности:** по итогам работы каждый студент сдаёт **отчёт** (файл формата .odt). Все результаты команд нужно фиксировать сразу — копировать вывод терминала в заготовку отчёта по ходу выполнения.

# Практическая часть

## Задание 0: Определение дистрибутива и структуры загрузки

Прежде чем что-либо менять, выясните, с какой системой вы работаете и как она устроена. Все выводы команд копируйте в заготовку отчёта (раздел «Задание 0»).

1. Определите дистрибутив:

```bash
cat /etc/os-release
```

2. Выясните, какая команда GRUB доступна в вашей системе:

```bash
which update-grub grub-mkconfig grub2-mkconfig
```

3. Найдите, где реально лежит конфиг GRUB:

```bash
ls -la /boot/grub/grub.cfg /boot/grub2/grub.cfg 2>/dev/null
```

4. Посмотрите текущую разметку диска и точки монтирования:

```bash
lsblk -f
```

5. Определите реальные параметры, с которыми загружено ваше ядро (отсюда мы возьмем правильные UUID и имена файлов):

```bash
cat /proc/cmdline
```

> **Что зафиксировать в отчёте (Задание 0):**
> - название и версия дистрибутива;
> - доступная команда GRUB и её полный путь;
> - путь к реальному конфигу GRUB;
> - имя раздела с /boot и его UUID (из lsblk -f);
> - UUID корня (/) из вывода cat /proc/cmdline (параметр root=);
> - версия загруженного ядра.
>
> Эти данные понадобятся в задании 2.

---

## Задание 1: Исследование текущей конфигурации GRUB

1. Изучите текущую конфигурацию GRUB:

```bash
cat /etc/default/grub
```

2. Просмотрите сгенерированный файл конфигурации (используйте путь, найденный в задании 0):

```bash
sudo cat /boot/grub/grub.cfg | head -50
# или
sudo cat /boot/grub2/grub.cfg | head -50
```

3. Определите текущие параметры ядра:

```bash
cat /proc/cmdline
```

4. Посмотрите, какие скрипты участвуют в генерации конфига:

```bash
ls -la /etc/grub.d/
```

> **Что зафиксировать в отчёте (Задание 1):** фрагмент /etc/default/grub (первые 30 строк конфига); значение `GRUB_CMDLINE_LINUX_DEFAULT`; список скриптов из /etc/grub.d/.

## Задание 2: Добавление нового пункта меню в GRUB

1. Создайте резервную копию конфигурации:

```bash
sudo cp /etc/default/grub /etc/default/grub.backup
```

2. Добавьте новый пункт меню, создав файл:

```bash
sudo nano /etc/grub.d/40_custom
```

3. Добавьте содержимое, подставив свои значения из задания 0:

- `UUID_РАЗДЕЛА_BOOT` — UUID раздела с /boot (из `lsblk -f`);
- `UUID_КОРНЯ` — UUID корневого раздела (из `cat /proc/cmdline`, параметр root=);
- `ВЕРСИЯ_ЯДРА` — имя файла ядра из /boot/ (например, `6.12.01-generic-24rosa13-x86_64`).

```bash
#!/bin/sh
exec tail -n +3 $0

menuentry "Linux (Recovery Mode)" {
    load_video
    insmod gzio
    insmod part_gpt
    insmod ext2
    search --no-floppy --fs-uuid --set=root UUID_РАЗДЕЛА_BOOT
    linux /vmlinuz-ВЕРСИЯ_ЯДРА root=UUID=UUID_КОРНЯ ro single
    initrd /initrd-ВЕРСИЯ_ЯДРА.img
}
```

> ⚠️ **Обратите внимание!**
> - В GRUB нельзя использовать `$(uname -r)` — загрузчик не умеет выполнять shell-команды. Версию ядра нужно писать явно.
> - Имена файлов ядра и initrd различаются: в Debian/Ubuntu/Astra это `/vmlinuz-ВЕРСИЯ` и `/initrd.img-ВЕРСИЯ`, а в Fedora/ROSA/RHEL — `/vmlinuz-ВЕРСИЯ` и `/initrd-ВЕРСИЯ.img`. Проверьте командой `ls /boot/`.
> - Путь root= должен быть правильным. Посмотрите его в `cat /proc/cmdline` и скопируйте оттуда значение root=...

4. Сделайте файл исполняемым и **проверьте** генерацию во временный файл (чтобы не сломать загрузку):

```bash
sudo chmod +x /etc/grub.d/40_custom
sudo grub2-mkconfig -o /tmp/grub.test  # для ROSA/Fedora/RHEL
sudo grub-mkconfig -o /tmp/grub.test   # для Astra/Ubuntu/Debian
```

Если вывод заканчивается словом **завершено / done** и ошибок нет — применяйте по-настоящему:

```bash
sudo grub2-mkconfig -o /boot/grub2/grub.cfg  # ROSA / Fedora / RHEL
sudo update-grub                            # Astra / Ubuntu / Debian
# или
sudo grub-mkconfig -o /boot/grub/grub.cfg   # Astra / Ubuntu / Debian
```

5. Убедитесь, что запись появилась в конфиге:

```bash
grep -A8 "Recovery Mode" /boot/grub2/grub.cfg
# или
grep -A8 "Recovery Mode" /boot/grub/grub.cfg
```

> 🔴 **Если при генерации возникла синтаксическая ошибка — не применяйте конфиг!** Проверьте, что в вашем `40_custom` нет символов `$`, не осталось строки `exec tail -n +3 $0` в начале файла, и пути к ядру и initrd существуют (проверьте `ls /boot/`).

> **Что зафиксировать в отчёте (Задание 2):** итоговое содержимое `/etc/grub.d/40_custom`; вывод команды генерации (со словом **завершено**); фрагмент grub.cfg с вашей записью (вывод grep).

## Задание 3: Изменение параметров ядра

1. Отредактируйте файл настроек GRUB:

```bash
sudo nano /etc/default/grub
```

2. Найдите строку `GRUB_CMDLINE_LINUX_DEFAULT` и добавьте параметры (значение зависит от дистрибутива — на Astra имеет смысл `parsec.max_ilev=63`, на других системах этот параметр просто игнорируется):

```bash
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash net.ifnames=0"
```

3. Обновите конфигурацию GRUB (команда — по вашей системе из задания 0):

```bash
sudo grub2-mkconfig -o /boot/grub2/grub.cfg  # ROSA / Fedora / RHEL
sudo update-grub                            # Astra / Ubuntu / Debian
```

4. Перезагрузите систему и проверьте новые параметры:

```bash
sudo reboot
```

```bash
cat /proc/cmdline
```

5. Убедитесь, что добавленный параметр появился в выводе. Если да — задание выполнено верно.

> **Что зафиксировать в отчёте (Задание 3):** строка `GRUB_CMDLINE_LINUX_DEFAULT` до и после изменения; вывод `cat /proc/cmdline` после перезагрузки; краткий вывод о том, применился ли параметр.
