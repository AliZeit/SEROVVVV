# Генератор лабораторных отчётов ODT

Комплект для репозитория [AliZeit/SEROVVVV](https://github.com/AliZeit/SEROVVVV): Python-генератор, заполняемый шаблон и инструкция для ИИ-агента. Подготовлен по образцу **«ЛР-1. Ткаченко.odt»** и **СТАНДАРТУ 01-2023 Университета «Сириус»** из репозитория.

Это инструмент оформления, а не автоматическое доказательство выполнения лабораторной. Генератор не запускает команды из задания и не сочиняет результаты.

## Что находится в комплекте

| Файл | Назначение |
|---|---|
| `report.py` | Генератор ODT из JSON |
| `requirements.txt` | Зависимости Python |
| `SKILL.md` | Инструкция для ИИ-агента: как подготовить данные и проверить результат |
| `examples/template.json` | Пустой заполняемый шаблон содержания |
| `examples/demo.json` | Демонстрация на первых трёх шагах `lab1/TASK.MD` |
| `examples/assets/` | Три оригинальных снимка экрана из `lab1` |
| `output/Шаблон_отчета.odt` | Шаблон, который можно редактировать в Writer без Python |
| `output/Пример_генерации.odt` | Демонстрационный черновик со встроенными снимками экрана |
| `output/*.pdf` | Предпросмотр этих документов |
| `references/formatting.md` | Требования стандарта, номера пунктов и отличия от образца |
| `test_report.py` | Автоматические проверки генератора |

## Быстрый старт

Требуется **Python 3.10 или новее**. Для создания ODT LibreOffice не нужен; для обновления оглавления, проверки страниц и экспорта PDF рекомендуется LibreOffice Writer.

```bash
python -m venv .venv
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Затем из каталога комплекта:

```bash
python -m pip install -r requirements.txt
python report.py examples/template.json -o output/my_report.odt
python report.py examples/demo.json -o output/demo.odt
python -m unittest -v test_report.py
```

**Для своей работы:** скопируйте `examples/template.json`, заполните реквизиты и содержание, затем запустите генератор с новым файлом. Пример не привязан к `lab1`: данные для `lab2`, `lab3`, `lab4`, `lab5` и `Astra_lab` подготавливаются аналогично.

## Как устроены данные

Обязательные строки верхнего уровня: `title`, `discipline`, `student`, `group`, `teacher`, `year`. Также нужен непустой массив `sections`.

Дополнительные поля:

- `lab_number` — номер лабораторной;
- `department`, `program` — подразделение и направление;
- `teacher_position`, `date` — должность руководителя и дата выполнения;
- `draft: true` — пометка «ШАБЛОН / ЧЕРНОВИК — НЕ ДЛЯ СДАЧИ»; выключайте её только после проверки;
- `toc: true` — оглавление; `false` отключает его.

Не переносите ФИО Ткаченко, группу и дату из образца как свои. Заполнители намеренно оставлены в квадратных скобках.

Раздел содержит `title`, необязательное `numbered: true` и массив `blocks`. Нумеруемые разделы получают номера автоматически. Введение, заключение и список источников оставляйте без номера.

### Абзац и подзаголовок

```json
{"type": "paragraph", "text": "Результат настройки приведён на рисунке {fig:network}."}
```

```json
{"type": "heading", "text": "Настройка сети"}
```

Подзаголовок в первом нумеруемом разделе получит номер `1.1`. Основные разделы начинаются с новой страницы.

### Изображение

```json
{
  "type": "figure",
  "id": "network",
  "path": "../../SEROVVVV/lab1/8.png",
  "caption": "Настройка сетевого адаптера"
}
```

- Пути отсчитываются **от каталога JSON**, а не от каталога запуска команды.
- Допускаются PNG и JPEG; изображение встраивается в ODT, поэтому внешний файл после генерации не нужен.
- `id` должен быть уникальным и содержать латинские буквы, цифры, `_` или `-`.
- `{fig:network}` в абзаце заменяется актуальным номером рисунка при генерации. Это **не динамическое поле Writer**: после перестановки рисунков меняйте JSON и генерируйте файл заново.
- Подпись формируется как `Рисунок 1.1 — Настройка сетевого адаптера`. Нумерация начинается заново в каждом основном нумеруемом разделе, но не в каждом подразделе.
- Изображения масштабируются с сохранением пропорций, без обрезки; максимальная ширина 16,5 см, высота 17 см. Читаемость мелкого текста проверяйте вручную.
- Рисунок и его подпись удерживаются вместе средствами стилей Writer.

### Небольшая таблица

```json
{
  "type": "table",
  "caption": "Параметры виртуальной машины",
  "rows": [
    ["Параметр", "Значение"],
    ["Оперативная память", "4 Гбайт"],
    ["Виртуальный диск", "50 Гбайт"]
  ]
}
```

Генератор добавит название `Таблица 1.1 — …` над таблицей. Все ячейки — строки JSON. Это базовая поддержка небольших таблиц: повторение шапки, переносы больших таблиц и надписи «Продолжение таблицы» нужно оформлять отдельно.

### Источники и контрольные вопросы

Обычные абзацы в соответствующем разделе. Библиографические записи, номера источников и ссылки `[1]` не создаются автоматически: используйте реальные источники в порядке первого упоминания. Контрольные вопросы включайте, если они есть в задании. Генератор не проверяет научную достоверность текста и полноту ответов.

## Оформление

- A4; левое поле 30 мм, правое 15 мм, верхнее и нижнее 20 мм.
- Times New Roman, 14 пт, чёрный цвет.
- Основной текст: интервал 1,5, по ширине, первая строка 1,25 см.
- Подписи и текст таблиц: одинарный интервал.
- Заголовки: полужирные, по центру; для нумеруемых основных разделов — прописные буквы.
- Титульный лист учитывается в общей нумерации, но номер на нём не выводится.
- На остальных страницах — номер по центру нижнего колонтитула.
- Настоящее оглавление ODF по заголовкам двух уровней; после новой генерации его нужно обновить в Writer.

**Шрифт:** генератор задаёт Times New Roman, но не поставляет и не встраивает его. На компьютере без этого шрифта редактор подставит замену. В среде проверки использовалась подстановка Liberation Serif; поэтому PDF — технический предпросмотр, а не гарантия окончательных переносов на вашем компьютере.

## Перед сдачей

1. Установите Times New Roman из законного источника, если его нет в системе.
2. Откройте ODT в LibreOffice Writer.
3. Выполните **Сервис → Обновить → Обновить всё** (Tools → Update → Update All); при необходимости обновите оглавление через его контекстное меню. Сохраните документ.
4. Проверьте титульный лист: он должен занимать одну страницу. Очень длинные реквизиты могут потребовать корректировки отступов.
5. Сверьте каждое утверждение со снимками экрана и реальным результатом. Не оставляйте незаполненные поля.
6. Проверьте читаемость рисунков, подписи, ссылки, переносы таблиц и номера страниц.
7. Сверьте объём с заданием. Стандарт рекомендует **10–16 страниц без приложений**, но не следует добирать их пустыми листами. Шаблон и короткий демонстрационный фрагмент этот объём не имитируют.
8. Уберите `draft` только после проверки. Перегенерация перезаписывает ODT: ручные правки в нём не переносятся обратно в JSON.
9. Экспортируйте PDF и осмотрите все страницы. ODT сохраните как редактируемый исходник.

## Что ещё нужно для полноценного отчёта

Номер/каталог лабораторной, актуальное задание, подтверждённые результаты и снимки экрана, ФИО и группа, дисциплина, данные руководителя и дата. Методические указания преподавателя нужны, если они уточняют структуру, вопросы или обязательные проверки.

Стандарт и образец уже достаточны для **основы оформления**. Дополнительный ГОСТ «на всякий случай» не нужен: при специфических элементах (формулы, приложения, сложные таблицы, листинги) обратитесь к соответствующим пунктам стандарта и указанным в нём нормативным документам.

## Как использовать SKILL.md

Положите весь комплект в каталог проекта, например `tools/lab-report/`, и передайте агенту `SKILL.md` вместе с заданием. Это переносимая инструкция в формате навыка, а не установленный плагин. Порядок регистрации навыка зависит от конкретной среды агента.

Пример запроса:

> Используй `tools/lab-report/SKILL.md`. Подготовь отчёт по `lab3/TASK.MD`. Сначала проверь все снимки экрана и составь JSON; неизвестные реквизиты спроси у меня. Не добавляй непроверенные результаты. Сгенерируй ODT, обнови оглавление в LibreOffice и проверь PDF.

## Границы реализации

Не реализованы автоматическое чтение произвольного Markdown в готовый научный отчёт, OCR снимков, формулы, приложения с буквенной нумерацией, сложные листинги и полностью автоматическая проверка соответствия стандарту. Генератор отделяет содержание от оформления и поддерживает наиболее частые элементы лабораторных по ИТ.

Исходный репозиторий не изменялся удалённо; коммитов и pull request не создавалось. Файлы подготовлены отдельным комплектом.
